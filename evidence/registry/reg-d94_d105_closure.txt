REG-D94..REG-D105 — closure record for the 2026-09-30 WAF red-team and seccomp lockdown pass
===========================================================================================

Branch claude/aegis-v4-comprehensive-audit-m2qyka. Every item was fixed in
f3e7bb1 on top of 8e03b31. 8e03b31 is the head of PR #225, which main carries
as the squash commit 3d7bc69; `git diff 8e03b31 3d7bc69` is empty, so the
"before" tree is also main's. For each item this record gives what was
observed at 8e03b31 before the fix and what was observed on the branch after it.

Environment: Linux 6.18 x86_64 container, Python 3.11 venv with the hash-locked
runtime, libseccomp.so.2, and the aegis_rust extension rebuilt from the branch
(maturin, release profile). The seccomp probes run as root. An unprivileged
gateway takes the same code paths, except that SQLite skips `fchown`.

Method
------
HTTP: one probe script drives the three model endpoints through
`fastapi.testclient` with a mocked upstream (`LLMForwarder` patched) and real
authentication (`auth_disabled=False`). It was run twice from the same
interpreter: once with PYTHONPATH pointing at a git worktree of 8e03b31, with
the aegis_rust wheel that was installed before the Rust change, and once at the
branch with the rebuilt wheel.
The first output line names the source tree the import resolved to.
`forwarded` counts calls that reached the mocked provider. `rejection_id` is
the `x-aegis-rejection-id` header of a durable rejection node.

Seccomp: small child-interpreter scripts build the ledger or store, load the
real filter with `SeccompGuard.apply_filter()` (with `_is_sandbox` forced to
False so the production path runs), then do the work the configured feature
does after lockdown. Exit 159 is the shell's 128 + SIGSYS (31): the kernel
killed the process. Missing syscalls were identified with `strace -f` and added
one at a time until the flow survived. The resulting set is `SQLITE_SYSCALLS`
below.

None of these probe scripts is committed as a tool. The committed tests below
reproduce every finding without them.

How the SQLite set was derived: the default profile already carried
SQLITE_SEQUENCE_STORE_SYSCALLS (for the HA sequence store) but loaded it only
for ha_sequencer_url=sqlite. Under strace the archive journal and the
shredding vault died in turn at pread64, geteuid, fchown (root only: SQLite
hands the journal to the database owner) and pwrite64. Adding each one and
re-running reached exit 0. The union is SQLITE_SYSCALLS. Nothing in it can
create a process, map executable memory or open a socket.

The probe's own SIGSYS: one early probe was killed after its work finished.
The cause was the probe script's TemporaryDirectory cleanup (rmdir) running
after lockdown, which is an artifact of the harness, not the gateway. The
committed tests create their directories before the filter loads and leave
cleanup to pytest in the parent.
