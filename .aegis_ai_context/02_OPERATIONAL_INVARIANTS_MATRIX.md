## Interpretation

A passing invariant test means only that the named executable or model check passed in its declared scope. It does **not** establish universal correctness, production fitness, compliance, certification, accepted capacity, cryptographic-module validation, publication, or provenance. Four facts remain independent: historical immutable source baseline **`fdace8844568eb788216740b2cb5daf187d99d3b`** has **14 `4.0.0` anchors**; historical published GitHub Release **v4.0.1** uses a lightweight tag targeting **`6469904380218584ae0b5221334bc9a46500f5ba`**; prior public PyPI/npm `aegis-latent-sdk` packages were observed at **4.0.0** without attributing them to failed workflows; and the **source release target v4.1.2** has 14 synchronized `4.1.2` anchors and was **published on every surface and read back on 2026-09-04: signed annotated tag at `860f14177d94c194e5ae7156017d6fa74264e429`, GitHub Release with 31 assets, PyPI `aegis-latent-core` `4.1.2`, PyPI `aegis-latent-sdk` `4.1.2`, npm `aegis-latent-sdk` `4.1.2`, and GHCR gateway and dashboard images carrying cosign signature objects. `cosign verify` and `gh attestation verify` were not run. External lifecycle state must be independently read back and is never encoded by source metadata; the statement above rests on the 2026-09-03 readback.
