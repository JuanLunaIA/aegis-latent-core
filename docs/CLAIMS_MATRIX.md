## Product category

Aegis is an **OpenAI-compatible AI Governance and Evidence Gateway**. It sits between an application and an upstream model provider and applies request policy and security controls. For admitted non-streaming outcomes, it commits governed request/response evidence to a durable signed ledger before returning the response. For admitted SSE, it emits sanitized events incrementally and commits one exact-byte terminal summary before emitting the terminal marker. It is not an LLM, a universal WAF, a universal compliance product, a legal-admissibility decision, or a substitute for organizational security controls.

| `CLM-054` | The native WAL's frame-bounds arithmetic is model-checked over all `usize` inputs. | `IMPLEMENTED` | `mod verification` in `aegis_rust_v2/src/wal.rs`; Kani 0.67.0; `Kani Model Checking` CI job; [Formal Verification §Kani](formal/FORMAL_VERIFICATION.md#kani-bit-level-model-checking) | Covers `header_range` and `payload_range` only. Kani models no `mmap`, no `flush_range`, no filesystem and no concurrency, so this establishes nothing about durability, crash consistency, power-loss behaviour, or that `capacity` equals the mapped length. It does not make the WAL memory-safe as a whole and is not a whole-system refinement proof. |
| `CLM-055` | A failed commit leaves the MMR exactly as it was, at a cost independent of chain length. | `IMPLEMENTED` | `MerkleMountainRange.checkpoint()` / `rollback_to()`; `tests/test_mmr_rollback.py`; `tests/test_crypto_audit_rollover.py` | The rollback token is O(log N) and exact, verified against a `deepcopy` restore. It is a correctness and cost property of one in-process structure; it establishes no throughput figure and no durability property. |
| `CLM-056` | Exactly one process may append to a WAL path, enforced rather than documented. | `IMPLEMENTED` | `aegis/core/crypto_audit.py` (`_lock_wal_fd`, `WalWriterConflictError`) | POSIX advisory locking via `fcntl.flock`. Advisory locks bind cooperating processes on the same host and the same filesystem; they do not constrain a writer that bypasses the code path, a second host on shared storage, or an NFS mount where `flock` semantics differ. On platforms without `fcntl` the guard logs a warning and discipline remains operator-enforced. |
| `CLM-057` | Streaming redaction fails closed only on candidates the detectors could still match. | `IMPLEMENTED` | `aegis/core/streaming_deidentifier.py`; `tests/test_proxy_streaming.py`; [PII Redaction Boundaries §3](privacy/PII_REDACTION_BOUNDARIES.md#streaming-the-bounded-holdback-and-its-fail-closed-edge) | Each open-candidate check is a viable-prefix test against the detector that would redact the text. The `ADDRESS` pattern's street-name run is bounded at 40 characters and the guard mirrors that bound, so a viable candidate (at most 46 characters) always fits the 64-character minimum window and the abort is structurally unreachable. The cost is recall: a street name longer than the bound is no longer redacted, in the streaming and non-streaming paths alike, and `tests/test_phi_address_bound.py` asserts that cost directly. Redaction remains best-effort pattern matching; see `CLM-024`. |
| `CLM-058` | Reopening a native WAL segment with a smaller capacity preserves committed frames. | `IMPLEMENTED` | `RustWal::open` in `aegis_rust_v2/src/wal.rs`; `reopening_with_a_smaller_capacity_does_not_truncate_the_segment` | The requested capacity is a floor; a segment only grows. This is a data-preservation property of the auxiliary segment on open. It does not change the segment's auxiliary role (`CLM-045`) and establishes no durability guarantee. |
| `CLM-059` | Governed requests are refused while the evidence chain is known to be broken. | `IMPLEMENTED` | `_require_intact_ledger` in `aegis/proxy/app.py`; `tests/test_app_wal_corrupt.py`; [Failure Semantics §4](architecture/FAILURE_SEMANTICS.md) | Triggered by the ledger's own `_fault_state`, which is set when startup replay stops at a malformed line. It does not detect corruption that replay parses successfully, corruption introduced after startup, or tampering outside the WAL. `/health` and `/metrics` deliberately remain reachable while traffic is refused. |

## Required wording controls

Use **“implements controls aligned with”** instead of **“satisfies compliance.”** Use **“timing leakage was not detected under the named experiment”** instead of **“constant-time.”** Use **“offered load”** instead of **“capacity.”** Use **“independently verifiable per-replica evidence bundle”** instead of **“globally ordered multi-region audit trail.”** Use **“static demo telemetry”** instead of **“live telemetry”** for material under `Samples/`.

## External reference boundary

Framework references are contribution mappings and review lenses. NIST AI RMF is a voluntary framework, and ISO/IEC 42001 is an AI management-system standard; neither reference certifies this repository. Primary sources for the v3.1.0 baseline are registered in `evidence/market_hardening_v3_1/documentation_source_register_v3_1_0.md`. Framework mappings do not determine legal applicability or replace a customer assessment.

## Falsification protocol

A public claim is blocked when its source path changes, the named regression or benchmark fails, the workload boundary changes without rerun, a deployment prerequisite is absent, an independent reviewer identifies a contradiction, or a customer-facing document uses stronger language than this matrix. Every future claim must add a locator, evidence artifact, boundary conditions, and a falsification test before publication.
