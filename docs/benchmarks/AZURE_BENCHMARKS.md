## How to read this

- **A durable commit costs about one `fsync` on this disk.** The commit p50 (3.98 ms) sits next to the raw `fsync` p50 (3.56 ms). The retained local run's 0.62 ms is a different storage device, not a faster gateway. Read the [Storage Requirements](../operations/STORAGE_REQUIREMENTS.md) power-loss section before treating either figure as a durability statement.
- **Throughput rose between 10 and 50 threads here and did not on the local host.** The local run's note that throughput "does not scale with thread count" describes that host. The Azure result is consistent with the group-commit engine amortizing a slow `fsync` across concurrent commits. No experiment here isolated that cause.
- **Single writer still holds.** All figures are one process and one WAL. They are not a multi-replica figure, and Azure Disk gives one WAL one attached machine.
- **Two runs agree.** A first run on the same VM, whose artifact was replaced after a field-extraction fix in the `fio` step (it recorded `null` for `fsync` latency), gave commit p50 3.99 ms and 1,245 / 2,483 / 2,491 commits per second at 10 / 50 / 100 threads. Only the second artifact is retained.

## What this does not establish

| Not established | Why |
| --- | --- |
| Any capacity or request rate | No governed HTTP traffic was generated; the upstream provider path was not measured |
| Behavior of other sizes, regions, or Standard SSD or Ultra disks | One configuration |
| Power-loss durability of Premium SSD | `fsync` acknowledged is not the same as media-durable; no power-loss test was run |
| Variance across days or noisy neighbors | One session, two runs, minutes apart |
| Kernel-level firewall enforcement | The gateway logged that no `nft` or `iptables` backend was available in the container, so blocks are application-layer only |
| The AKS path | The AKS overlay was not deployed or measured |

## Reproduce

```bash
python deploy/azure/kit-creator/aegis_azure_kit.py doctor --region <region> --vm-size <size>
python deploy/azure/kit-creator/aegis_azure_kit.py create --name bench --region <region> --ssh-source auto
cd aegis-azure-kits/bench && ./deploy.sh
deploy/azure/benchmarks/run_remote.sh aegis-azure-kits/bench <pushed-git-sha>
./teardown.sh
```

`run_remote.sh` copies `deploy/azure/benchmarks/run_azure_benchmarks.sh` to the VM, runs it as root, and writes `evidence/benchmarks/azure/azure_<size>_<region>_<date>.json`. Retain the artifact and its SHA-256 before quoting any number, and describe your environment as this page does.
